## Kế hoạch implement bằng Claude Code (đề xuất, chưa phải dữ kiện nguồn)

**Code paths dự kiến:** `src/saber/subtasks/t0182_003/` · `scenarios/t0182_003/` · `tests/subtasks/test_t0182_003.py`.

1. Viết `spec.json` có schema JSON/Pydantic của output; không tự suy ra giá trị enum, tolerance còn mơ hồ phải đưa vào adjudication.
2. Viết fixture builder hoặc data adapter đọc hiện vật đầu vào, chốt seed, split, checksum và ground truth độc lập.
3. Tạo runner đọc file bất biến, nộp output JSON, validate schema và chấm bằng grader độc lập. Nếu output là rule có thể chạy, sandbox verifier với timeout và giới hạn tài nguyên.
4. Tests: mẫu dương/mẫu âm, đáp án rỗng, output sai schema, thiếu hiện vật, leakage, tính quyết định (determinism).

**Gate thao tác:** Không — mặc định read-only hoặc chỉ mô phỏng; nếu định thực thi thay đổi trạng thái cần phê duyệt riêng.



## Acceptance / checklist

- [ ] Có `spec.json`/Pydantic output DTO với field, enum, normalization và tolerance đã ký duyệt; không chỉ lưu tên field trong string.
- [ ] Có fixture/snapshot với **nguồn input và checksum**, nhãn private tách khỏi agent, cùng một `episode_id` độc lập.
- [ ] Có scorer deterministic cho từng item, kiểm chứng tổng trọng số và hard gates với case golden.
- [ ] Có positive, benign hard-negative, invalid/missing-data, cross-episode và unauthorized tests phù hợp.
- [ ] 2 lần chạy cùng seed, snapshot và config cho kết quả giống nhau ở các phần deterministic.
- [ ] Có log thực thi, bản ghi provenance, actual command/test outputs; trạng thái VERIFIED chỉ khi tests đã chạy.
- [ ] Không ảnh hưởng production hoặc hệ thống ngoài range; tác vụ cần thay đổi trạng thái chỉ chạy sau approval.
