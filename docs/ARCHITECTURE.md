# SABER architecture — implementation design

## Objective

SABER evaluates autonomous and coordinated **defensive SOC workflows** against replayable scenarios involving realistic benign workload and **authorized, isolated** attack emulation. Separate: (1) real lab, (2) agent/data plane, (3) independent benchmark control and evaluator.

## Architecture boundaries

```text
                        SABER CONTROL PLANE (trusted)
 operator → run scheduler → scenario registry → snapshot controller
                    │               │
                    │       PRIVATE manifest + independent verifier
                    │               └──────────────┐
                    ▼                              ▼
      +-----------------------+         +------------------------+
      | ISOLATED CYBER RANGE  |         | BENCHMARK EVALUATOR    |
      | Windows/Linux/Web/DB  |         | hidden truth; scoring  |
      | benign work + approved|         | write-once run reports |
      |   attack emulation    |         +------------------------+
      +-----------------------+                    ▲
                    │ telemetry                    │ evidence + actions
                    ▼                              │
      +-----------------------+         +------------------------+
      | COLLECT / NORMALIZE   |────────▶| EVENT SEARCH GATEWAY   |
      | Sysmon/Linux/Wazuh    |         | bounded query DSL/API  |
      | raw archive; indexer  |         +------------------------+
      +-----------------------+                    │ only bounded tools
                                                   ▼
                                      +---------------------------+
                                      | AGENT WORKFLOW ORCHESTRATOR|
                                      | Monitor  Hunt Content  IR  |
                                      | case state, budgets, audit  |
                                      +---------------------------+
```

**Critical:** The arrows above are permissions, not just network flow. Blue agents must never be able to call private manifest, evaluator, snapshot controller or attack runner APIs. Their prompts also must not contain scenario family labels or test split.

## Deployment profiles

### Local development — default until M1 passes

- `docker compose` starts PostgreSQL, MinIO (optional before T017) and mock services.
- `FakeEventStore` reads deterministic fixture events and simulates visibility times.
- `DryRunResponseAdapter` records proposals but does not alter hosts.
- No live cyber attack execution and no external dependencies in CI.
- Dev fixtures may have labels to test graders; do not use their scores for claims about model quality.

### Isolated lab — gated in M2

- Proxmox-managed VLAN/bridge with firewall deny-by-default, no routes to enterprise/Internet targets, tightly scoped package installation exceptions as explicitly approved.
- Windows workstation, Linux web server, Linux database, workload runner, log collector. Add network sensor if physical budget permits; AD and extra nodes are v0.2.
- Wazuh manager and agent for collection, Wazuh Indexer/OpenSearch for searchable documents. **The Wazuh manager API is not assumed to be the generic raw-search API.** Keep distinct adapters.
- Raw event objects in MinIO (hash + version + retention); PostgreSQL for run metadata and provenance.
- Snapshot baseline restore and health checks before each episode. Operator-approved emulation uses fixed allowlisted scenario profiles and independent success verification.

The package is a **modular monolith** for v0.1, not a premature microservice fleet. Modules depend inward on typed ports/protocols; implementation adapters cannot be imported by `domain`. Use constructor injection for event stores, providers, range driver and IR driver.

## Domain ports (Python Protocols)

- `EventStore.search(query, visibility_cutoff)` returns page + continuation token; no unbounded read.
- `RawEvidenceStore.put/get(sha256, immutable_ref)` returns immutable object reference.
- `RangeController.plan/health/restore` has no exposed arbitrary command endpoint.
- `WorkloadDriver.start/stop/status` uses trusted workload IDs.
- `EmulationDriver.list_allowlisted/execute/status` accepts only signed/allowlisted scenario IDs with operator approvals.
- `AttackVerifier.verify()` returns `VERIFIED`, `NOT_VERIFIED`, or `INDETERMINATE` with provenance.
- `LLMProvider.generate(messages, tools, budget, ...)` returns normalized usage, failures and actual model identifiers.
- `ResponseDriver.plan/preview/execute/rollback` only whitelisted lab actions.
- `Grader.grade(observation, sealed_truth)` is evaluator-only and never injected into Blue tools.

## Data plane and access control

1. Workloads and emulation generate real endpoint/application/network activity.
2. Collectors ingest raw telemetry. Normalize into internal canonical model; record parsing errors rather than dropping them.
3. Agent queries are authenticated, filtered by episode, host scope, budget and as-of visibility; time travels are forbidden.
4. Agents create evidence-backed findings, cases, rule proposals and response requests via narrow APIs.
5. Evaluator receives those outputs plus **sealed, separately stored ground truth** after the episode ends and computes metrics.
6. Persist exact version hashes: repository commit, scenario family, environment snapshot, model/provider, prompt hash, rule registry hash, dataset split, data coverage, seeds and tool version.

## Important decisions

| Topic | Decision | Why |
|---|---|---|
| Orchestration | Small durable Python state machine | Deterministic transitions and replay, no extra orchestration dependency yet |
| Persistence | PostgreSQL | Serializable metadata; event/report references |
| Telemetry query | Neutral constrained DSL + backends | Same tools for synthetic and Wazuh Indexer/OpenSearch |
| Content | Sigma AST/pySigma with explicit mapping tests | Sigma conversion depends on backend and field mapping; no magic native Wazuh deployment |
| Baselines | Rules-only, single LLM, specialized/no-sharing, shared-state multi-agent | Measures incremental benefit of agent coordination |
| IR | Default dry-run | Real-world safety and scientific track separation |
| UI | Last, read-mostly | Avoid UI-first while contracts and metrics still move |

## Configuration

`SABER_ENV=dev|lab`, `SABER_TELEMETRY_BACKEND=fake|opensearch`, `SABER_RESPONSE_MODE=dry-run|approved-lab`, `SABER_MODEL_PROVIDER=stub|anthropic|openai` (provider adapters optional). Secret values must be supplied by environment or protected secrets manager, never in source. `lab` mode must fail closed if isolation proof or approval is missing.

## Observability

Use structured JSON logs with `trace_id`, `run_id`, `episode_id`, `case_id`, `tool_call_id`, request duration and explicit error category; never log raw provider credentials. Every tool call stores arguments after secret redaction, result IDs, start/stop times, side-effect type and authorization decision.

## Release gate

No claims about end-to-end autonomous SOC effectiveness until measured with hidden episodes using real telemetry, attack success verification, split isolation, uncertainty intervals and a reproducible independent evaluator.
